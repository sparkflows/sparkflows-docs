Read channel history
====================

.. container:: tutorial-intro

   Returns the messages of one channel, newest first, each with ts, user, text, thread\_ts and reply\_count; thread replies are not included.

Before you start
----------------

* A Slack connection. See :doc:`how to set one up </agentic-ai-guide/tools-integrations/connector-tools/slack>`.

Add this step
-------------

#. Drag **App Action** from **Commonly used** onto the canvas and connect it where the step belongs.
#. **App:** choose **Slack**.
#. **Action:** under **Channel**, choose **Read channel history**.
#. **Details:** choose your Slack connection, click **Test**, then fill in the boxes below.
#. Click **Load the fields from Slack** so later steps can use the columns, then **Save action**.

Fill in the details
-------------------

Type a value, or click a field under **What arrives here** to put a value from an earlier step into the box.

.. list-table::
   :header-rows: 1
   :widths: 26 12 62
   :class: tool-params

   * - Box
     - Required
     - What to enter
   * - **Channel**
     - No
     - The channel's id, which a Channel list returns. Posting a message also takes a name such as #general; reading a channel takes only the id. For example ``C0123ABC, the channel id``.
   * - **Fields to return**
     - No
     - Comma-separated field names. Blank returns the default set. For example ``text, user, ts``.
   * - **Limit**
     - No
     - How many rows at most. A run from the canvas previews 20. Default: ``100``.

Under **Advanced settings**:

.. list-table::
   :header-rows: 1
   :widths: 26 12 62
   :class: tool-params

   * - Box
     - Required
     - What to enter
   * - **Extra query parameters (JSON)**
     - No
     - Sent to the API unchanged, for a filter this form has no field for. For example {"timeMin": "2026-09-01T00:00:00Z"}.
   * - **Nested fields**
     - No
     - Some records keep a value inside another value, such as a priority inside an issue. This decides how those inner values become columns.

       * ``deep`` (default): Every inner value gets its own column, named with dots, such as ``fields.priority.name``.
       * ``oneLevel``: Only the first level is split. Anything deeper stays in one column as JSON text.
       * ``json``: Each inner value stays whole, in one column of JSON text.

       See the example below the table.

**Nested fields, by example.** Take a record ``{"id": 7, "fields": {"priority": {"name": "High"}}}``. Each choice gives you these columns:

.. list-table::
   :header-rows: 1
   :widths: 20 80
   :class: tool-table

   * - Choice
     - Columns you get
   * - ``deep``
     - ``id`` = ``7`` and ``fields.priority.name`` = ``High``
   * - ``oneLevel``
     - ``id`` = ``7`` and ``fields.priority`` = ``{"name": "High"}``
   * - ``json``
     - ``id`` = ``7`` and ``fields`` = ``{"priority": {"name": "High"}}``

Keep ``deep`` unless a later step needs the whole inner value as JSON.

What it passes on
-----------------

The records come out as rows, one per record. Click **Load the fields from Slack** to see the columns before you save.

A run from the canvas previews 20 rows, whatever **Limit** says.

Start a flow from it
--------------------

A :doc:`Trigger </agentic-ai-guide/triggers-automation/triggers>` can watch Slack with this action and start the flow when something new turns up. Pick **Slack** in the Trigger, then the event.

.. list-table::
   :header-rows: 1
   :widths: 32 68
   :class: tool-table

   * - Event
     - What it reports
   * - **Message posted in a channel**
     - Channel is the channel id, for example C0123ABC, which a Channel list returns. Reports each new message posted in the channel.
   * - **Message containing text**
     - Channel is the channel id, for example C0123ABC, which a Channel list returns, and Filter the text to look for, matched regardless of case. Reports each new message in the channel whose text contains it.
   * - **Member mentioned in a channel**
     - Channel is the channel id, for example C0123ABC, which a Channel list returns, and Filter the member's user id, for example U0123ABC. Reports each new message in the channel that mentions the member.
   * - **Message posted by a member**
     - Channel is the channel id, for example C0123ABC, which a Channel list returns, and Filter the member's user id, for example U0123ABC. Reports each new message the member posts in the channel.

Let an agent decide instead
---------------------------

To let an agent call **Read channel history** only when a request needs it, add the :doc:`Read channel history tool </agentic-ai-guide/tools-integrations/connector-tools/slack/channel-history>` to an Agent Node.
