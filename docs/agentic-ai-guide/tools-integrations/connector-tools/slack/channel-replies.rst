Read thread replies
===================

.. container:: tutorial-intro

   Returns one thread: the parent message followed by its replies, oldest first, each with ts, user and text. Needs the channel ID and the parent message's ts from Channel history or Message search.

Before you start
----------------

* A Slack connection. See :doc:`how to set one up <../slack>`.

Add it to your agent
--------------------

#. In Agent Studio, open the **Tools** group and click **Add tools**, or click **+ Tool** on an Agent Node.
#. Choose **Slack** under **Connectors** and connect your Slack connection.
#. Tick **replies** in the **Channel** row, then click **Add to agent**.

The agent now sees ``slack_channel_replies`` and calls it when a request needs it.

What the agent fills in
-----------------------

The agent fills these in from each request. To pin a value so the agent cannot change it, set it under **Fixed settings**.

.. list-table::
   :header-rows: 1
   :widths: 22 14 12 52
   :class: tool-params

   * - Parameter
     - Type
     - Required
     - What it means
   * - ``channel``
     - text
     - Yes
     - The channel ID, for example C0123ABC; Channel getMany finds it from the channel's name.
   * - ``threadTs``
     - text
     - Yes
     - The ts of the thread's parent message, for example 1712345678.000100.
   * - ``fields``
     - list of text
     - No
     - Columns to keep, for example ["text", "user"]; a dotted name reaches inside an object, such as profile.email. Blank keeps them all. Example: ts,user,text.
   * - ``limit``
     - whole number
     - No
     - How many messages at most, the parent included. Default: 50.

Need it on every run?
---------------------

To run **Read thread replies** every time a flow reaches it, without the agent deciding, use the :doc:`Read thread replies App Action </agentic-ai-guide/tools-integrations/app-action-apps/slack/channel-replies>`.
