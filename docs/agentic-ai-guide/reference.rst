Reference
=========

Reference documentation provides the detailed technical information needed after a user understands the conceptual workflow. It should be optimized for lookup rather than narrative reading.

Sparkflows reference pages can document processor parameters, connector configuration, supported model providers, vector stores, APIs, permissions, errors, and other product-specific settings. These pages should be generated and maintained close to the product implementation so they remain accurate as capabilities change.

Reference content should link back to task-oriented guides. For example, a user reading a processor reference should be able to jump to a tutorial showing how that processor is used in an agentic workflow.

Start here
----------

Use the task-oriented documentation first when learning a capability. Use Reference when you need exact configuration fields, supported values, parameters, permissions, or error information.
